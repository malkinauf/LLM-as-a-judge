# LLM-as-a-Judge

A Python-based evaluation framework for investigating how large language models (LLMs) assess the correctness of responses generated by other language models.

The framework integrates selected evaluation datasets, adapted to a common data format, and enables systematic comparisons of three prompting strategies: Baseline, Second-Level, and Dynamic Prompting.

## What can you do with this project?

- Evaluate responses generated by other language models using three prompting strategies: **Baseline**, **Second-Level**, and **Dynamic Prompting**.
- Configure and run experiments through an interactive Jupyter-based interface or directly through a notebook.
- Run evaluations on selected benchmark datasets that have been adapted to a common data format.
- Compare evaluation results across different judge models, prompting strategies, and datasets.
- Calculate evaluation metrics and track experiment results, execution time, and token usage, with optional logging to **Weights & Biases (W&B)**.

## Quick start

### 1. Clone the repository

```bash
git clone https://github.com/malkinauf/LLM-as-a-judge.git
cd LLM-as-a-judge/evaluation-pipeline
```

### 2. Create an environment and install the package

```bash
python -m venv .venv
source .venv/bin/activate  # Linux/macOS
python -m pip install -e .
```

On Windows, activate the environment using `.venv\Scripts\activate`.

### 3. Configure the model provider

See [`evaluation-pipeline/.env.example`](evaluation-pipeline/.env.example) for the environment variables used by the pipeline. Configure the required credentials for your selected provider; do not commit secrets.

### 4. Open the experiment notebook

From `evaluation-pipeline/`, start Jupyter:

```bash
jupyter notebook
```

Then open one of these notebooks:

- [`notebooks/experiment_app.ipynb`](evaluation-pipeline/notebooks/experiment_app.ipynb) — interactive experiment setup.
- [`notebooks/run_experiments.ipynb`](evaluation-pipeline/notebooks/run_experiments.ipynb) — notebook-based experiment execution.

> Notebook execution may require additional provider credentials or runtime setup. Consult the pipeline documentation before running a large batch.

## Evaluation strategies

| Strategy | General idea |
| --- | --- |
| **Baseline** | Evaluate a response directly using the selected criterion. |
| **Second-Level** | Perform a further evaluation step based on a first-level judgment. |
| **Dynamic** | Adapt the evaluation prompt using an additional preliminary step. |

The exact prompts and variants are defined in the pipeline configuration.

## Running tests

From `evaluation-pipeline/`:

```bash
python -m pip install -e ".[test]"
python -m pytest tests/ -v
```

The `test` optional dependency group is part of the updated local configuration; ensure it is committed to the repository.
