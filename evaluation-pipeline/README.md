# LLM-as-a-Judge Evaluation Pipeline

A Python-based pipeline for studying how large language models evaluate responses generated by other language models. It brings selected, previously adapted datasets into a common evaluation workflow and supports comparisons across judge models, datasets, and prompting strategies.

## What this pipeline supports

- **Baseline:** A judge evaluates a model-generated response directly.
- **Second-Level:** A second evaluation reviews an initial judgment.
- **Dynamic Prompting:** Preliminary analysis is generated before the final judgment.
- **Experiment tracking:** Evaluation metrics, execution information, and optional Weights & Biases (W&B) logging.

## Requirements

- Python 3.10 or newer
- Jupyter Notebook or JupyterLab
- Access to the model provider(s) you intend to use (local setup or API credentials, depending on provider)

## Installation

Open a terminal in the `evaluation-pipeline/` directory:

```bash
python -m pip install -e .
```

To install test dependencies as well:

```bash
python -m pip install -e ".[test]"
```

> The test extra above assumes your updated `pyproject.toml` contains `[project.optional-dependencies]` with a `test` group.

## Quick start

Choose **one** workflow:

| Workflow | Notebook | When to use it |
| --- | --- | --- |
| Interactive interface | [`notebooks/experiment_app.ipynb`](notebooks/experiment_app.ipynb) | Select and configure experiments through a Jupyter UI |
| Notebook configuration | [`notebooks/run_experiments.ipynb`](notebooks/run_experiments.ipynb) | Configure and run experiments directly in notebook cells |

1. Install the package from `evaluation-pipeline/`.
2. Open your chosen notebook in Jupyter.
3. Configure the model provider and required credentials/runtime before running evaluations.
4. Select an available prepared dataset, judge model, and prompting strategy.
5. Start with a small test run before launching a larger batch.

**Note:** The exact provider setup depends on the environment (for example, local execution or Kaggle) and the selected model.

## Data and evaluation

The pipeline works with **selected datasets that have been adapted for this project**, rather than automatically accepting arbitrary datasets. Prepared evaluation examples include the question, the response to be judged, and a reference label. Criterion-specific prompt configurations define how judgments are requested.

The pipeline computes evaluation metrics and can optionally log results to W&B. When interpreting metrics, also inspect coverage: not every model output necessarily produces a valid, usable judgment.

## Run the tests

From `evaluation-pipeline/`:

```bash
python -m pip install -e ".[test]"
python -m pytest tests/ -v
```
